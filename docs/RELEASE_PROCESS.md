2. Update CHANGELOG.md with the new version number, changes, and release date.
3. Commit and push these changes to the trunk branch.
4. Tag the commit with the new version number (e.g. v1.2.3) and push the tag.
5. Build the release version of the mod
6. Create a new release on GitHub, using the new tag, and upload the built mod as an asset.
7. Update the resources/repository.json file with the new version number and download URL for the new release.
8. Commit and push the updated repository.json file to the trunk branch.
